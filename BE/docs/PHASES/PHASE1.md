# Phase 1 — 기반 구축

## 목표

**소셜 로그인이 된다.** 이후 모든 로그인 연계 기능의 전제조건이라 가장 먼저 만든다.

## 이 단계에서 만드는 것

| 기능 | PRD 번호 |
|---|---|
| 소셜 로그인 (Google, Kakao) | F-01 |
| 회원 만들기 / 찾기 | F-01 |
| 약관 동의 기록 | F-01 |

> 회원탈퇴와 마이페이지는 Phase 3에서 만든다. 이 단계에서는 "들어오는 것"만 만든다.

## 하는 일

### 1. 소셜 로그인 받기

로그인은 Google·Kakao가 대신 확인해준다. 서버는 **"이 사람이 진짜 맞다"는 증표만 받아서** 회원을 찾거나 새로 만든다. 비밀번호는 우리가 갖지 않는다.

- 처음 온 사람이면 회원을 새로 만든다.
- 이미 있는 사람이면 기존 회원을 찾는다.
- 전화번호는 묻지 않는다. 추가로 물어보는 정보도 없다.
- 목업 로그인 화면엔 Google·Apple·Kakao가 있으나, 이번 범위는 **Google·Kakao** (Apple 제외). 카카오 `sign_in_provider` 문자열은 프론트와 맞춰 확정 (`docs/DETAIL_SPEC.md` 6-1 #19, 2026-08-30).

### 2. 회원 정보 보관

| 항목 | 비고 |
|---|---|
| 소셜 계정 식별값 | 이 사람이 누구인지 구분하는 값 |
| 어느 소셜인지 | Google / Kakao |
| 이메일, 닉네임 | 소셜에서 받아옴 |
| 국적, 언어 | **자리만 만들어 둔다.** 실제로 고르는 화면은 Phase 2의 메인 화면 |
| 약관 동의 시점 | 언제 동의했는지 날짜까지 |
| 가입일 | |
| 탈퇴 여부, 탈퇴일 | 자리만 만들어 둔다. 실제 탈퇴 기능은 Phase 3 |

### 3. 로그인 여부 판단하는 공통 장치

즐겨찾기·리뷰처럼 **로그인이 필요한 기능이 "이 사람 로그인했나?"를 물어볼 곳**을 만든다. Phase 3에서 여러 기능이 이걸 그대로 가져다 쓴다.

## 완료 기준 체크리스트

- [ ] 구글 계정으로 로그인하면 회원이 새로 만들어진다
- [ ] 카카오 계정으로 로그인하면 회원이 새로 만들어진다
- [ ] 같은 계정으로 다시 로그인하면 회원이 또 만들어지지 않고 기존 회원을 찾아온다
- [ ] 전화번호를 묻지 않고 가입이 끝난다
- [ ] 이메일·비밀번호로 가입하는 길은 아예 없다
- [ ] 약관 동의 시점이 회원 정보에 날짜로 남는다
- [ ] 잘못됐거나 만료된 증표로 접근하면 거부하고 "다시 로그인하세요"라고 안내한다
- [ ] 로그인이 필요한 자리에 로그인 없이 접근하면 "로그인이 필요한 기능입니다"가 나온다
- [ ] 회원 정보에 국적·언어·탈퇴 여부를 담을 자리가 준비되어 있다

## 넘어가기 전 확인

- 이 단계에서는 **화면에 보여줄 명소 데이터가 아직 없다.** 확인은 로그인 자체로만 한다.
- 국적·언어는 자리만 만들고 값을 채우지 않는다. 채우지 않은 사람은 한국어를 기본으로 본다(PRD F-02).

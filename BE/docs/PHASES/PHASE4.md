# Phase 4 — 확장 기능

## 목표

**코스와 다국어를 붙인다.** 둘 다 앞 단계에서 만든 것 위에 얹는 기능이다.

## 왜 마지막인가

두 기능 모두 **먼저 알아봐야 할 것이 남아 있다.**

| 기능 | 남은 것 |
|---|---|
| 코스 | 코스 관련 데이터를 담을 자리가 설계 단계에서 아직 빠져 있다 |
| 다국어 번역 | 번역을 어떤 방식으로 할지 미확정 (LLM 기반 검토 중) |

앞 단계처럼 바로 만들기 시작할 수 없고, **간단히 만들어 보고 되는지 확인하는 과정**이 먼저 필요하다.

## 이 단계에서 만드는 것

| 기능 | PRD 번호 |
|---|---|
| 코스 추천 | F-08 |
| 외부 공유 | F-09 |
| 다국어 번역 | N-01 |
| 고유명사 음역 | N-01 |

## 4-1. 코스 추천

### 하는 일

- 코스는 **근처 식당 1곳 + 카페 1곳 + 그 외 1곳**(소품샵, 박물관, 다른 명소 등)으로 구성한다 (PRD F-08)
- 코스를 저장하고 편집할 수 있다
- 코스를 만들 때만 로그인이 필요하다. 보는 것은 로그인 없이 가능
- 명소 상세 화면에서 코스로 들어간다
- 저장한 코스를 마이페이지에 추가한다
- 즐겨찾기에 코스도 저장할 수 있게 한다

### 먼저 해야 할 일

- **코스를 담을 자리를 만든다.** 코스 하나 / 코스에 들어가는 장소들 / 순서
- **주변 상권을 저장할지 정한다.** Phase 2에서는 카카오맵에서 그때그때 받아오기로 했는데, 코스에 넣으려면 "이 코스에 이 식당이 들어있다"를 기록해야 한다. 가게가 폐업했을 때 어떻게 할지 함께 정해야 한다
- 관리자 등록 · 사용자 등록 · AI 추천 중 **이번에 어디까지 할지 정한다.** PRD에 AI 추천은 MVP가 아니라고 적혀 있다

## 4-2. 외부 공유

- 명소와 코스를 공유할 수 있다
- 이번 단계에서는 **링크 복사만** 만든다. 다른 채널은 나중에 (PRD F-09)
- 공유받은 사람은 **로그인 없이** 내용을 볼 수 있다

## 4-3. 다국어 번역

### 언제 번역하는가

| 대상 | 시점 | 이유 |
|---|---|---|
| 명소·작품 설명 | 관리자가 등록할 때 미리 | 개수가 적고 거의 안 바뀜. 손님은 즉시 보게 됨 |
| 리뷰 | 누군가 처음 열어볼 때 | 계속 늘어나고 안 읽힐 것도 많음. 한 번 번역하면 저장해서 다음 사람부터 즉시 |

원래 언어와 보는 사람의 언어가 같으면 번역하지 않는다. **그래서 Phase 3에서 리뷰의 원래 언어를 기록해 둔 것이다.**

### 고유명사는 음역한다

한국 고유명사는 **뜻을 옮기지 않고 소리 나는 대로** 적는다.

- `경복궁` → `Gyeongbokgung` (○)
- `경복궁` → `Gyeongbok Palace`, `Scenery Palace` (×)

손님이 현지에서 길을 묻거나 표지판을 찾을 때 실제로 통하는 표기여야 하기 때문이다. 뜻으로 옮긴 이름은 한국에서 아무에게도 통하지 않는다.

음역 대상: 지명과 순우리말 (PRD N-01)

### 번역 실패를 어떻게 판단하는가

**(1) 확실한 실패 — 기계가 판단할 수 있음**

| 기준 | 설명 |
|---|---|
| 답이 안 옴 | 번역 서비스가 오류를 돌려줌 |
| 시간 초과 | 정해둔 시간 안에 안 옴 |
| 빈 값 | 결과가 텅 비어 있음 |
| 원문과 똑같음 | 한국어를 넣었는데 한국어가 그대로 나옴 |
| 길이가 터무니없음 | 원문의 1/5보다 짧거나 5배보다 김 |

기다리는 시간은 두 곳이 다르다. **명소·작품은 30초**(아무도 안 기다림), **리뷰는 5초**(사람이 화면 열고 기다리는 중).

길이 검사는 **20자가 넘는 글에만** 적용한다. 한글 한 글자를 소리대로 옮기면 로마자 서너 자가 되어서, 짧은 이름에 이 규칙을 쓰면 멀쩡한 번역을 실패로 오해한다. (`청계천` 3자 → `Cheonggyecheon` 14자 = 4.7배)

**(2) 애매한 실패 — 기계가 못 잡음**

경복궁을 `Scenery Palace`로 번역해 온 경우다. 답은 멀쩡히 왔고 길이도 정상이고 문법도 맞다. 기계 입장에서는 성공인데 우리 핵심 규칙을 어겼다. 자동으로 100% 잡는 방법은 없다.

| 대상 | 막는 방법 |
|---|---|
| 명소·작품 | **관리자가 눈으로 확인하고 승인해야** 손님에게 보인다 |
| 리뷰 | 기계 검사만 하고, 이상하면 신고 기능으로 걸러낸다 |

명소는 몇 백 개 수준이고 한 번 확인하면 끝이라 감당할 만하다. 리뷰는 계속 늘어나 사람이 다 볼 수 없고, 개인 감상이라 오역의 피해도 작다.

### 실패하면 어떻게 하는가

| 대상 | 처리 |
|---|---|
| 리뷰 | 즉시 원문 표시. 재시도하지 않음(사람이 기다리는 중). 다음에 누가 또 열면 그때 재시도 |
| 명소·작품 | 실패 목록에 남기고 관리자가 "다시 번역"을 누른다. **자동 재시도 없음** — 실패가 반복되면 비용만 나감 |

**번역이 없으면 무조건 한국어 원문을 보여준다.** 번역은 외부에 맡기는 일이라 언젠가 반드시 실패한다. 그때 화면이 통째로 안 뜨는 것보다 한국어라도 보이는 편이 낫다.

### 검색과의 관계

명소 이름을 언어별로 저장하고 나면, **Phase 2에서 만든 검색이 번역 이름까지 뒤지도록 넓혀야 한다.** 그래야 외국인이 `Gyeongbokgung`으로 검색해서 찾을 수 있다. 이 작업을 빠뜨리면 화면만 영어고 검색은 한국어로만 되는 상태가 된다.

## 완료 기준 체크리스트

**코스**
- [ ] 코스를 담을 자리가 만들어져 있다 (코스 / 들어가는 장소 / 순서)

**공유**
- [x] ~~명소와 코스의 링크를 복사할 수 있다~~ → 프론트엔드가 현재 페이지 주소를 클립보드에 복사하는 UI 동작이라 백엔드 작업이 없다(2026-08-20, 사용자 확인)

**번역**
- [ ] 관리자가 명소를 등록하면 번역문이 만들어진다
- [ ] 승인하기 전에는 손님에게 번역문이 보이지 않는다
- [ ] 승인하면 그 언어를 고른 손님에게 번역문이 보인다
- [ ] `경복궁`이 `Gyeongbokgung`으로 나온다 (뜻으로 번역되지 않는다)
- [ ] 외국어로 쓴 리뷰를 처음 열면 번역되고, 두 번째부터는 즉시 나온다
- [ ] 원래 언어와 보는 언어가 같으면 번역하지 않는다
- [ ] 번역이 실패하면 화면이 깨지지 않고 한국어 원문이 나온다
- [ ] 번역이 실패한 명소가 관리자 화면의 실패 목록에 남는다
- [ ] 짧은 명소 이름이 길이 검사 때문에 실패로 처리되지 않는다
- [ ] **영어로 `Gyeongbokgung`을 검색하면 경복궁이 찾아진다**

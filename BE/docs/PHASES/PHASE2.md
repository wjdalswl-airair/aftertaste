# Phase 2 — 핵심 탐색 (비로그인 가능 범위)

## 목표

**로그인하지 않은 사람이 "촬영지를 찾아본다"는 핵심 가치를 끝까지 체험할 수 있다.**

여기까지가 탐색형 MVP의 마지노선이다. 이 단계가 끝나면 서비스가 무엇인지 남에게 보여줄 수 있다.

## 이 단계에서 만드는 것

| 기능 | PRD 번호 |
|---|---|
| **명소·작품 데이터 채우기** | F-05 |
| 메인 화면 (배너, 국적 선택) | F-02 |
| 통합검색 (장소 + 작품) | F-03 |
| 드라마 / 영화 구분 조회 | F-03 |
| 위치기반 추천 — 비로그인 분기만 | F-04 |
| 명소 상세 + 카카오맵 연동 | F-05 |

> **명소·작품 데이터 채우기를 맨 앞에 넣었습니다.**
> 원래 목록에는 없었는데, 검색·추천·상세가 전부 명소 데이터 위에서 돌아갑니다. 이게 없으면 나머지 다섯 개를 만들어도 확인할 방법이 없습니다.

## 하위 단계

Phase 2는 아래 5단계로 나눠서 진행한다. 각 단계마다 coding→test→verify→review 루프를 돈다.

| 단계 | 내용 |
|---|---|
| 2-1 | 명소·작품 데이터 채우기 (가장 먼저 — 나머지 전부의 기반) |
| 2-2 | 메인 화면 |
| 2-3 | 검색 |
| 2-4 | 위치기반 추천 |
| 2-5 | 명소 상세 + 카카오맵 |

## 하는 일

### 2-1. 명소·작품 데이터 채우기 (가장 먼저)

- 공공데이터에서 촬영지 목록을 **가져온다**.
- 가져온 명소에 관리자가 **장면 설명·사진·작품 연결**을 채워 넣는다.
- 공공데이터 원본 번호를 같이 저장한다. 나중에 데이터를 다시 받아올 때 "이건 이미 가진 명소"임을 알아보기 위해서다. 이게 없으면 받아올 때마다 같은 명소가 중복으로 쌓인다.
- 관리자가 직접 채운 내용은 다시 가져오기를 해도 덮어쓰지 않는다.

**한 명소에 여러 작품이 찍히고, 한 작품이 여러 명소에서 찍힌다.** 그래서 둘을 잇는 자리를 따로 두고, 장면 설명은 그 자리에 붙인다. 같은 남산타워라도 작품마다 나온 장면이 다르기 때문이다.

**번역문을 담을 자리도 지금 만들어 둔다.** 실제 번역은 Phase 4지만, 자리를 나중에 만들면 명소·작품 데이터를 크게 갈아엎어야 한다.

### 2-2. 메인 화면

| 구성 요소 | 이번 단계 |
|---|---|
| 슬라이드 배너 | 만든다. 관리자가 주간 콘텐츠를 넣는다 |
| 국적 선택 | 만든다. 고르지 않으면 한국어 |
| 명예의 전당 | **만들 수 없다** — 아래 참고 |
| Top10 캐러셀 | **만들 수 없다** — 아래 참고 |

> **명예의 전당과 Top10은 이 단계에서 채울 수 없습니다.**
> PRD 기준으로 명예의 전당은 "그 주(週) 좋아요가 가장 많은 후기의 대표 사진"(2026-08-28: 월→주), Top10은 "즐겨찾기가 가장 많은 명소"입니다. 둘 다 리뷰·즐겨찾기 데이터가 필요한데, 그건 Phase 3에서 생깁니다.
> 이 단계에서는 **자리만 비워두고, Phase 3이 끝난 뒤에 채웁니다.** Phase 3 문서에 할 일로 적어뒀습니다.

### 2-3. 검색

- 하나의 검색창에서 장소와 작품을 함께 찾고, 결과는 **명소 섹션 / 작품 섹션**으로 나눠서 보여준다.
- 작품만, 드라마만, 영화만 골라 볼 수 있다.
- 글자를 치는 도중 이름 후보를 보여준다(자동완성).
- 글자가 비슷하면 잡아준다. 오타나 끝글자 누락도 찾아준다.
- 결과가 없으면 "검색결과가 존재하지 않습니다".

**로그인한 사람의 검색어를 지금부터 쌓아둔다.** 이걸 쓰는 건 Phase 3의 추천 고도화지만, **지금부터 모으지 않으면 Phase 3 시작 시점에 쓸 데이터가 하나도 없다.**

### 2-4. 위치기반 추천 — 비로그인 분기만

| 상황 | 이번 단계 |
|---|---|
| 위치 권한 **허용** | 현재 위치 주변의 촬영 명소 3곳을 추천 |
| 위치 권한 **거부** | 위치 없이 명소 3곳을 무작위로 추천 |
| 로그인 + 검색이력 반영 | **Phase 3에서** |

추천 개수는 3개, 반경은 현위치에서 가장 가까운 명소까지의 거리를 기준으로 한다(PRD F-04).

**위치 권한 거부 시 추천 기준**은 PRD "남은 결정 사항"에 미결로 남아 있던 항목이다. 즐겨찾기 개수 기준으로 하자는 의견이 있었지만, 즐겨찾기 모델·데이터가 아직 없어(Phase 3에서 생김) Phase 2에서는 만들 수 없다. 그래서 이번 단계는 **무작위 3곳**으로 구현한다(2026-08-19).

### 2-5. 명소 상세 + 카카오맵

한 화면에 함께 나가는 것:

- 명소 기본 정보 (이름·주소·사진·영업시간)
- 이 명소가 나온 작품 목록 + 작품별 장면 설명
- 작품 정보 (제목, 방영 시기, 주연배우, 감독)
- 지도 위 위치
- 주변 상권 — **우리가 저장하지 않고 카카오맵에서 그때그때 받아온다.** 상권은 폐업·신규가 잦아서 저장해두면 금방 틀린 정보가 된다
- 길찾기는 우리가 만들지 않고 카카오맵으로 넘긴다

리뷰 목록과 즐겨찾기 표시는 Phase 3에서 이 화면에 붙는다.

**주변 상권 조회 방식**: 백엔드가 프록시한다. 명소 상세 API가 명소의 좌표를 기준으로 카카오 장소 검색 API(REST, `KAKAO_API_KEY`)를 대신 호출해서 결과를 함께 내려준다. 프론트가 카카오 SDK로 직접 부르는 방식도 있었지만, 이미 있는 `places/sources/kakao_geocoding.py`의 서버측 카카오 연동 패턴과 일관되고 REST 키를 서버에만 두는 게 안전해서 이 방식으로 정했다(2026-08-19, 사용자 확인).

**주변 상권 검색 기준**: 반경 1km 내에서 카카오 카테고리 검색(음식점 FD6 + 카페 CE7 + 관광명소 AT4)을 합쳐서 보여준다(2026-08-19, 사용자 확인).

## 완료 기준 체크리스트

**2-1. 명소·작품 데이터**
- [ ] 공공데이터에서 명소 목록을 가져와 실제 데이터가 채워진다
- [ ] 같은 데이터를 두 번 가져와도 명소가 중복으로 쌓이지 않는다
- [ ] 관리자가 채운 장면 설명·사진이 다시 가져오기를 해도 사라지지 않는다
- [ ] 명소 하나에 작품 여러 개를, 작품 하나에 명소 여러 개를 연결할 수 있다
- [ ] 번역문을 담을 자리가 준비되어 있다 (아직 비어 있어도 됨)

**2-2. 메인 화면**
- [ ] 로그인 없이 메인 화면이 열린다
- [ ] 관리자가 넣은 배너 콘텐츠가 보인다
- [ ] 국적을 고를 수 있고, 고른 값이 남는다
- [ ] 국적을 고르지 않으면 한국어로 보인다

**2-3. 검색**
- [ ] 로그인 없이 검색된다
- [ ] 결과가 명소 섹션과 작품 섹션으로 나뉘어 나온다
- [ ] 드라마만, 영화만 골라 볼 수 있다
- [ ] 오타를 내도(`경보궁`) 찾아진다
- [ ] 결과가 없으면 "검색결과가 존재하지 않습니다"가 나온다
- [ ] 글자를 치는 도중 후보가 나온다
- [ ] 로그인한 사람의 검색어가 서버에 쌓인다

**2-4. 추천**
- [ ] 로그인 없이 추천이 나온다
- [ ] 위치 권한을 허용하면 주변 명소 3곳이 나온다
- [ ] 위치 권한을 거부해도 화면이 깨지지 않고 추천이 나온다

**2-5. 명소 상세**
- [ ] 로그인 없이 열린다
- [ ] 명소를 열면 등장 작품과 작품별 장면 설명이 같이 나온다
- [ ] 지도에 위치가 표시된다
- [ ] 길찾기를 누르면 카카오맵으로 넘어간다
- [ ] 주변 상권이 보인다
- [ ] 없는 명소를 열려고 하면 "존재하지 않습니다"가 나온다

## 넘어가기 전 확인

- **명예의 전당·Top10은 비어 있는 상태가 정상이다.** Phase 3이 끝나야 채울 수 있다.
- 화면은 전부 한국어로만 나온다. 다국어는 Phase 4다.

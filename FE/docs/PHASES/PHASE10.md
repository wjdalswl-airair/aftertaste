# Phase 10 — 다국어 전체 적용

## 목표

**국적 선택에 따라 전체 화면의 UI 문구가 번역되어 보인다.**

## 이 단계에서 만드는 것

| 기능 | PRD 번호 |
|---|---|
| 언어별 UI 문구 리소스 (react-i18next) | N-01 |
| 지금까지 만든 모든 화면에 번역 키 적용 | N-01 |

## 하는 일

### 1. 언어 리소스 작성

- `src/i18n/`에 언어별 리소스 파일을 만든다.
- 지원 언어 목록은 이 문서 작성 시점에 BE와 확정되지 않았다(BE DETAIL_SPEC §7-8). 우선 한국어/영어로 시작하고, 언어가 늘어나면 리소스 파일만 추가되는 구조인지 확인한다.

### 2. 기존 화면에 적용

- Phase1~9에서 하드코딩한 한글 UI 문구(버튼, 라벨, 안내 메시지 등)를 전부 i18next 키로 교체한다.
- Phase2에서 만든 국적 선택 → `i18next.changeLanguage()` 연동이 실제로 전체 화면에 반영되는지 확인한다.

### 3. 서버 콘텐츠는 건드리지 않는다

- 명소·작품 설명, 리뷰 같은 콘텐츠는 BE가 이미 번역해서 내려준다(BE DETAIL_SPEC 4장). FE는 받은 값을 그대로 표시만 하고, 다시 번역을 시도하지 않는다.
- 고유명사 음역(예: 경복궁 → Gyeongbokgung)도 서버 응답에 이미 반영되어 온다. FE에서 별도 규칙을 적용하지 않는다.

## 완료 기준 체크리스트

- [ ] 국적을 바꾸면 버튼·라벨 등 UI 문구가 바뀐다
- [ ] 국적을 선택하지 않으면 한국어로 보인다
- [ ] Phase1~9에서 만든 화면에 하드코딩된 한글 문구가 남아있지 않다
- [ ] 서버에서 온 콘텐츠(명소 설명, 리뷰 등)는 FE가 다시 번역하려 하지 않고 그대로 표시한다
- [ ] 관련 유닛 테스트(국적 변경 시 `useLocaleStore` 갱신과 `i18next.changeLanguage()` 호출 연동) 통과 (Vitest)
- [ ] `npm run lint`, `npm run build` 통과

## 넘어가기 전 확인

- 지원 언어 목록이 확정되면 이 문서와 `docs/PRD.md` 6장을 함께 갱신한다.
- UI 문구 번역(i18next)과 서버 콘텐츠 번역은 서로 다른 시스템이라는 걸 헷갈리지 않는다 — 하나를 고친다고 다른 하나가 바뀌지 않는다.

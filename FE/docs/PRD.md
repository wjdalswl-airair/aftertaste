## 1. 이 문서의 범위

- 이 문서는 **어떤 화면에서 사용자가 무엇을 할 수 있는가**를 정의한다.
- 화면 구성 요소, API 연동 방식, 상태 관리 방식은 `docs/DETAIL_SPEC.md`에서 다룬다.
- 제품 전체 요구사항(F-01~F-11, N-01)은 `../../BE/docs/PRD.md`를 원본으로 한다. 이 문서는 그 내용을 FE 화면 단위로 재구성한 것이며, 내용이 서로 다르면 제품 PRD가 아니라 **더 최근에 사용자와 합의된 쪽**을 따른다. 불일치를 발견하면 임의로 고르지 말고 먼저 물어본다.

## 3. 화면별 사용자 행동 요구사항

### S-01. 온보딩 / 로그인
- 사용자는 Google 계정으로 로그인할 수 있다.
- 사용자는 Apple 계정으로 로그인할 수 있다.
- Kakao 로그인은 Figma 최신 로그인 모달에 있지만 이번 범위에서는 보류한다. (BE PRD F-01과 동일하게 Google/Apple만 구현. 추후 필요해지면 다시 논의.)
- 처음 로그인한 사용자는 별도 절차 없이 바로 이용할 수 있다 (추가 정보 입력 화면 없음).
- 약관·개인정보 동의는 첫 화면에 노출된다.
- 로그인하지 않아도 메인·검색·추천·명소 상세·리뷰 조회는 이용할 수 있다.

### S-02. 메인
- 사용자는 슬라이드 배너를 볼 수 있다.
- 사용자는 명예의 전당(해당 월 좋아요 수 최다 후기 사진)을 볼 수 있다.
- 사용자는 국적을 선택할 수 있다. 선택하지 않으면 한국어가 기본값이다.
- 사용자는 명소 TOP10(즐겨찾기 최다 10개)을 좌우로 넘겨 볼 수 있다.

### S-03. 검색
- 사용자는 하나의 검색창에서 장소와 작품을 함께 검색할 수 있다.
- 사용자는 드라마/영화를 나누어 볼 수 있다.
- 검색 결과 화면은 장소와 작품을 섹션으로 나누어 보여준다.
- 결과가 없으면 "검색결과가 존재하지 않습니다"를 보여준다.
- 사용자는 자동완성과 최근 검색어를 볼 수 있다.
- 로그인한 사용자의 검색 기록은 추천(S-04)에 반영된다.

### S-04. 추천 (위치 기반)
- 앱 진입 즉시 위치 권한 요청이 노출된다.
- 비로그인 + 위치 허용: 현재 위치 주변 촬영 명소를 추천받는다.
- 비로그인 + 위치 거부: 위치 없이 제공 가능한 기준으로 추천받는다.
- 로그인 + 위치 허용: 위치 + 검색 이력을 함께 반영한 추천을 받는다.
- 추천 개수는 3개다.

### S-05. 명소 상세
- 사용자는 카카오맵 기반 지도에서 명소 위치를 확인할 수 있다.
- 사용자는 명소명, 주소, 등장 작품 정보(제목·방영시기·주연배우·감독), 등장 장면 설명, 사진, 영업시간, 주변 상권, 리뷰를 볼 수 있다.
- 사용자는 카카오맵 길찾기로 연결할 수 있다.
- 사용자는 이 화면에서 코스(S-08) 진입할 수 있다.

### S-06. 즐겨찾기
- 로그인한 사용자는 명소를 즐겨찾기에 저장할 수 있다.
- 비로그인 사용자가 즐겨찾기를 누르면 "로그인이 필요한 기능"임을 안내한다.
- 명소뿐 아니라 코스도 즐겨찾기할 수 있다.
- 저장한 목록은 마이페이지(S-10)에서 확인한다.

### S-07. 리뷰
- 로그인한 사용자는 방문한 명소에 리뷰(별점/텍스트/사진)를 작성·수정·삭제할 수 있다.
- 한 명소에 리뷰를 여러 개 작성할 수 있다.
- 리뷰 조회는 비로그인도 가능하다.
- 다른 언어로 쓰인 리뷰는 번역되어 보인다.

### S-08. 코스
- 사용자는 명소 + 주변 상권(식당 1 + 카페 1 + 기타)으로 구성된 코스를 볼 수 있다.
- 로그인한 사용자는 코스를 저장·편집할 수 있다 (생성 시에만 로그인 필요).
- 명소 상세(S-05)에서 코스로 진입한다.

### S-09. 공유
- 사용자는 명소/리뷰/코스를 링크 복사로 공유할 수 있다.
- 공유받은 사람은 로그인 없이 내용을 볼 수 있다.

### S-10. 마이페이지
- 로그인한 사용자는 프로필, 즐겨찾기 목록, 내가 쓴 리뷰, 국적/언어 설정, 저장한 코스를 확인할 수 있다.
- 사용자는 프로필, 국적, 언어를 수정할 수 있다.

### S-11. 회원탈퇴
- 로그인한 사용자는 직접 탈퇴할 수 있다.
- 탈퇴 시 작성한 리뷰는 익명으로 남는다.
- 탈퇴 후 같은 계정으로 재가입할 수 있다.

## 4. 다국어(번역) 요구사항 ⭐

- 화면 전체가 사용자가 선택한 국적에 맞춰 번역되어야 한다.
- 한국 고유명사(지명 등)는 뜻을 옮기지 않고 음역(소리 나는 대로) 표기한다. 예: `경복궁` → `Gyeongbokgung`.
- 사용자가 작성한 리뷰도 번역 대상이다.
- 국적 선택과 화면 언어는 하나로 묶인다.
- ✍️ 지원 언어 목록, 번역 소스(자체 API vs 외부 번역 서비스)는 아직 미정.

## 5. 이번 범위에 포함하지 않는 것

- 코스 AI 추천, 코스 사용자 생성 UI (MVP 아님, 백엔드 PRD F-08 기준)
- 링크 복사 외 공유 채널(SNS 등)
- 리뷰 신고 UI (정책 미확정)

## 6. 기술 결정 사항 (FE 특화)

| # | 결정할 내용 | 결정 |
|---|---|---|
| 1 | 화면 지원 범위 | 모바일 전용. 데스크톱 대응 안 함. |
| 2 | 라우팅 구조 | React Router로 화면(S-01~S-11)을 페이지 단위로 분리한다. |
| 3 | 상태 관리 | Zustand로 전역 상태(로그인 여부, 국적/언어 등)를 관리한다. |
| 4 | 지도 연동 | 카카오맵을 사용한다 (Google Maps로 변경하지 않음 — 제안서·BE PRD F-05에 이미 명시됨). 카카오 공식 JS SDK를 `<script>` 태그로 직접 로드한다. |
| 5 | 다국어(번역) 처리 | react-i18next를 도입한다. |
| 6 | 인증 토큰 관리 | Firebase Auth SDK가 자체 관리한다 (`onAuthStateChanged`). FE는 직접 토큰을 저장하지 않고, API 호출 시 현재 유저의 idToken만 꺼내 헤더에 붙인다. |
| 7 | 디자인 시스템 / UI 라이브러리 | Figma "Yeoun Design System" 프레임(색상·타이포·버튼/카드/radius 토큰 정의됨)을 기준으로, MUI/Chakra 같은 기성 컴포넌트 라이브러리 대신 Tailwind CSS로 직접 구현한다. 토큰은 `src/index.css`의 `@theme`에 반영. 아이콘은 디자인에 명시된 대로 lucide-react 사용. |
